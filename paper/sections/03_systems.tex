This section describes the three harnesses of Table~\ref{tab:designpoints}
in the parts of the scheme, and then the instruction file of AutoDS-Tools.
Figure~\ref{fig:systems} draws them: blocks with a thin outline are fixed by
the harness, and blocks with a thick outline are decided by the model.

\subsection{FEDOT.LLM: a fixed-stage workflow}

FEDOT.LLM~\citep{fedotllm} pairs an LLM agent with the FEDOT
framework~\citep{nikitin2022fedot}. Control is fixed in four stages. Data
understanding extracts paths, column types, target, metric and submission
format. Configuration and code generation produce a FEDOT configuration and
fill a code template. Memory is the fixed input and output contract of each
stage. The execution loop runs the code in a sandbox and patches it until it
succeeds or a retry cap is reached. Reporting saves the script, the trained
pipeline and the predictions. The model builder is fixed: every task is
solved with FEDOT, which starts from a default pipeline for the task type
and searches over pipelines and tunes them when the time budget allows. The
workflow accepts tabular inputs only.

\subsection{AutoDS-Tools: a multi-agent system}

AutoDS-Tools~\citep{autodstools} coordinates six agents. Control is a plan
generated at run time. An Analyst explores the data, a Researcher studies
the target library and writes usage notes, and a Planner turns both into an
execution plan. Memory is the written reports: each agent writes a Markdown
report that the next one reads. In the execution loop a Coder refines the
solution against execution results, a Debugger handles execution errors
outside the main context, and a Presenter audits the result. The model
builder is open: the system may use any library installed in its container,
and its instruction file names one (Section~\ref{sec:file}).

\subsection{Terminus-2: a minimal single-agent harness}

Terminus-2 is the reference agent of
Terminal-Bench~\citep{merrill2026terminalbench}. Its only action is a shell
in a working directory. Control is left to the model, which chooses each
step: read the task statement, inspect the data, write code, run it and read
the output. Memory is one growing context. The execution loop is open and
ends when a submission is written or the budget is exhausted. The model
builder is the agent's own code, and the harness has no instruction file of
its own.

\subsection{The instruction file and its two parts}
\label{sec:file}

AutoDS-Tools comes with an expert instruction file that is composed on the
host and prepended to the task statement every agent reads. In current
terminology it is an agent skill~\citep{li2026skillsbench}: standing
procedural instructions, independent of the task. It has two parts, which
we measure separately.
\begin{description}
  \item[Library instruction.] Which library to use for the task family: a
        dedicated tabular AutoML library (LightAutoML~\citep{vakhrushev2021lightautoml})
        for tabular data, a vision, graph or transformer library for the other
        modalities. It states that the library is pre-installed and forbids a
        fallback to general-purpose estimators.
  \item[Discipline instruction.] How to train and how to check oneself:
        the validation protocol, handling of temporal shift, leakage checks,
        comparison against a trivial predictor, allocation of the time budget,
        the prohibition of degenerate submissions, and advice on training
        time.
\end{description}
On a tabular task the file is about 5$\times$ as long as the task statement,
and the library instruction is about a quarter of it. An ablation that
switches the whole file at once cannot tell the two parts apart.

In the scheme the file is knowledge about the procedure, and its library
instruction also sets the model builder. In FEDOT.LLM the library
instruction is the workflow itself: every task goes through FEDOT.
Terminus-2 has no instruction file of its own, so we test the file in a
second harness by appending it to the task statement
(Figure~\ref{fig:systems}).
