\section{Conclusion}
\label{sec:conclusion}

% Revised 26 October 2026 after Boukhanovsky's comment 8: one paragraph per
% hypothesis with its verdict, numbers, limit and use.

We asked where the accuracy and the reliability of agentic AutoML come
from. A general scheme separated the language model, the harness, the
instruction file and the model builder, and three hypotheses stated which
part decides which outcome. One open-weight 31B model ran under three
harnesses that cover three patterns of the scheme. They were tested on eight
real-world tabular tasks against eighteen tuned reference methods, on
MLAgentBench and on three scientific tasks.

\ref{hyp:harness}, the harness alone does not decide accuracy, held for
harnesses that leave the model to the agent. Without the instruction file
the mean normalised scores of a fixed-stage workflow, a six-agent system and
a minimal shell agent lie between $\nTerminus$ and $\nFedot$, and no pairwise
difference is significant. The harnesses differ where \ref{hyp:harness}
expects. Without the file AutoDS-Tools takes about
$\costRatioNoFileMed\times$ the median time of Terminus-2, Terminus-2 leaves
more MLAgentBench trials without a submission, and FEDOT.LLM accepts
tabular tasks only. With eight tasks this agreement does not prove equality,
and harnesses that search over candidate solutions were not tested.
\ref{hyp:harness} tells a designer what a harness can buy: reliability, time
and the range of tasks.

\ref{hyp:builder}, accuracy follows who builds and tunes the model, held
wherever the model builder changed. An agent writing its own code fits one
gradient-boosting configuration and never tunes it. The library instruction
makes AutoDS-Tools hand the modelling to LightAutoML, which searches and
tunes, and raises its score from $\nAutoDSOff$ to $\nAutoDS$. The library
instruction alone reaches $\nGridTool$, on par with tuned XGBoost. FEDOT.LLM
follows the same rule task by task. Maize shows the limit: a search tuned to
validation data unlike the test set transfers worse than a simple model. No
configuration reaches the strongest published method ($\nBest$).
\ref{hyp:builder} links agentic AutoML with the AutoML frameworks before it:
the agent gains accuracy by handing the search to a library, since it does
not run one on its own.

\ref{hyp:interaction}, the instruction file and the language model change
reliability in a direction set by the harness, held for both. AutoDS-Tools
completes its instruction file almost always. In Terminus-2 the whole file
leaves \ktBothLost{} of 24 trials without a submission and its library
instruction alone \ktToolLost{}, and on the scientific tasks the library
section left every Terminus-2 trial without one. From a working
script the file leaves \mlabWiped{} of \mlabRepeated{} MLAgentBench tasks
without a submission. A larger language model removes such trials under
Terminus-2 and adds them under AutoDS-Tools. \ref{hyp:interaction} makes an
instruction file or a language model part of the system under test. Its
effect has to be measured in each harness, and a leaderboard built around
one harness measures its instructions as well as its model.

Two experiments follow from the traces: a hyperparameter search added to the
agents that write their own code, under the same budget, and AutoDS-Tools
with its repair loop disabled, to measure the cost of the file without it.
