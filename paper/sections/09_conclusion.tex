\section{Conclusion}
\label{sec:conclusion}

% STAGE 4: shortened 21 September 2026; the numbers stay in Section 1 and in
% the Observation paragraphs, the conclusion names systems and baselines.

We isolated the architectural axis of agentic AutoML by holding the model
fixed and varying only the system around it, and we measured the result
against Optuna-tuned reference methods. Under one open 31B model the three
systems as deployed span $\spanShip$ on the normalised scale, from Terminus-2
to AutoDS-Tools at the level of tuned LightGBM, and no system reaches tuned
XGBoost or the strongest published method. What remains between AutoDS-Tools
and tuned XGBoost is search: Terminus-2 selects gradient boosting unaided and
writes one configuration, AutoDS-Tools hands the choice to LightAutoML, whose
tuning of a fixed model gains little, and FEDOT.LLM, whose backend searches
over models, beats every published method on one task and is level with
Terminus-2 over the eight.

Most of the six-agent system's lead over the open harness comes from the
instruction file it ships with (Section~\ref{sec:grid}), so the useful
question is which decision a piece of structure removes.
Constraint pays where it overrides a default the weak model gets wrong, and
costs where the default was already right. The same instruction file that
improves every TabReD task, where the agent starts from scratch, leaves
AutoDS-Tools with no submission on \mlabWiped{} of \mlabRepeated{} MLAgentBench
tasks, where a working script was already in place. Appended to the Terminus-2
task text it ends \ktBothLost{} of \ktBothTrials{} trials without a
submission, because the agent gives up on a fit that is still running. An
instruction file measured in one architecture has not been
measured in another, and we suggest this is the source of the disagreement
among published ablations of knowledge injection.

For practitioners the results give one rule per situation.
\begin{itemize}
\setlength{\itemsep}{0pt}
\item A strong tuned baseline exists: use it. The best system reaches tuned
  LightGBM and none reaches tuned XGBoost, and what separates them is
  hyperparameter search, which no system performs.
\item A tabular task from scratch, accuracy first, an hour per task
  acceptable: AutoDS-Tools with its instruction file. Without the file its
  lead over Terminus-2 is $\gapAgentsOff$ on the normalised scale, within the
  noise floor.
\item A first pass over a new scientific dataset, minutes per attempt:
  Terminus-2 with the task text alone. It matched or beat two author
  baselines and found the published featurisation on OpenPoly; every library
  or training-time instruction we added cost it trials.
\item A tabular task where search over a fixed backend pays: FEDOT.LLM,
  level with Terminus-2 on TabReD, best of the three on \texttt{ecom-offers}
  and on F-DATA, at $\minFedotTabredMin$ to $\minFedotTabredMax$ minutes a
  task with the column types supplied.
\item A working script is supplied: prescribe nothing. The file that improved
  all eight TabReD tasks left no submission on \mlabWiped{} of
  \mlabRepeated{} MLAgentBench tasks.
\end{itemize}
Three rules hold across at least two protocols and we state them in general
form. Prescribe only the decision the model would otherwise get wrong. Keep
advice about training time out of the prompt of any system with a hard time
limit: deleting two such paragraphs restored all \ktTrimTrials{} Terminus-2
trials. Search over models where the budget allows it: the one backend that
does so beats a published leaderboard on one task, while tuning a fixed model
inside AutoDS-Tools gained little. That the instruction file moves the result further
than a \axPriceSpread$\times$ backbone swap (Section~\ref{sec:modelaxis})
rests on three models, two from one vendor, and we report it as a result on
this domain without raising it to a rule.
