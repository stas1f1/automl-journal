Automation of data-science work has moved from AutoML frameworks to agents
built on large language models. The accuracy and reliability of such an
agent depend on four parts: the language model, the harness around it, the
instruction file and the procedure that builds the final model. We describe
a general scheme that separates these parts and test three hypotheses about
them. One open-weight 31B model runs under three harnesses: FEDOT.LLM (a
fixed-stage workflow over an AutoML library), AutoDS-Tools (a six-agent
system) and Terminus-2 (a minimal shell agent). Accuracy is measured against
eighteen tuned methods published with TabReD, scaled per task from 0
(weakest) to 1 (strongest). H1, the harness alone does not decide accuracy:
without the instruction file the three harnesses score $\nTerminus$ to
$\nFedot$, no pairwise difference is significant, and they differ in run
time and reliability. H2, accuracy follows who builds and tunes the model:
agents writing their own code fit one untuned gradient-boosting model. An
instruction that hands the modelling to an AutoML library raises
AutoDS-Tools from $\nAutoDSOff$ to $\nAutoDS$, the level of tuned LightGBM
and below the strongest published method ($\nBest$). H3, the instruction
file and the language model change reliability in a direction set by the
harness: in Terminus-2 the same file ends \ktBothLost{} of 24 trials without
a submission. A larger model removes such trials in one harness and adds them
in the other. An instruction file or a language model must therefore be
evaluated with its harness.
