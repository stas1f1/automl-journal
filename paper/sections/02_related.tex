\paragraph{Agentic AutoML systems} LLM-based systems for machine-learning
tasks range from workflows with fixed stages, where the model fills in
configurations or code templates, to multi-agent systems with planner,
coder and reviewer roles, to single agents in an open execution
loop~\citep{trirat2025automlagent,li2024autokaggle,guo2024dsagent,yang2025rdagent,kulibaba2025kompeteai,fang2025mlzero,lapin2025lightautods}.
In one recent system five agents turn a dataset and a goal stated in natural
language into an execution graph of services and repair the steps that
fail~\citep{bara2026thinkit}. Most
papers present one system and report an improvement over a previous one,
with the language model, the harness and the evaluation protocol all changing
between papers. Their ablations disagree: on MLE-bench the search structure
is the largest contributor in one system and has no measurable effect in
another, and the ranking of memory against search flips between
studies~\citep{toledo2025aira}. Such disagreement is expected when
interacting factors are removed one at a time on different language models
and task sets. A systematic mapping of agentic software engineering calls
for decision-level ablations and configuration comparisons for this
reason~\citep{diazvillegas2026mapping}.

\paragraph{How much the harness matters} Evidence from coding agents points
in two directions. With strong frontier models, elaborate harnesses add
little. A single session of a minimal coding agent matches four open-source
ML-engineering harnesses under the same language model and time
budget~\citep{brilliantov2026harness}. The advantage of complex harnesses
on issue repair shrinks as the model
improves~\citep{hu2026beyondmodel,kapoor2024agents}. With weaker models or
harder tasks, the harness is a large hidden variable. Aggregate scores span
$23.8$ points across harnesses evaluated
identically~\citep{harnessbench2026}, and harness choice induces a
40$\times$ spread in tokens per solved task~\citep{scaffoldeffect2026}. With
GPT-4o a purpose-built harness
earns medals in $8.7\%$ of competitions against $0.8\%$ and $4.4\%$ for two
general-purpose ones~\citep{chan2025mlebench}. GRACE-DS~\citep{tsymbalov2026graceds}, the
closest work in domain, structures the interaction of LLM-driven AutoML
agents on tabular tasks and finds that structure compresses the spread across
eight frontier language models of 80B to 1.6T parameters. We vary the harness under
one 31B language model, the complementary design, and read the spread against
tuned reference methods.

\paragraph{Knowledge in AutoML systems} AutoML systems have always held
knowledge about which methods work. auto-sklearn starts its search from
configurations that worked on similar earlier
datasets~\citep{feurer2015autosklearn}. Composite AutoML extends the search
to the structure of the pipeline, built by evolutionary search from a fixed
set of models and
operations~\citep{nikitin2022fedot,revin2023timeseries,nikitin2024sensitivity}.
Agents add knowledge in new forms. Besides the parametric knowledge of the
language model~\citep{xu2024conflicts}, DS-Agent retrieves earlier solutions through case-based
reasoning~\citep{guo2024dsagent}, KompeteAI retrieves Kaggle and arXiv
material~\citep{kulibaba2025kompeteai}, and AutoMind grounds its agent in a
curated knowledge base of expert practice~\citep{luo2025automind}. MLZero
embeds knowledge about library interfaces in its decision
process~\citep{fang2025mlzero}. Each of these systems adds knowledge
together with a new harness, so the effect of the knowledge is reported for
the system as a whole.

\paragraph{Explicit knowledge: instruction files and skills} Procedural
instructions mounted into a harness are now a distinct object of study. In agentic software
engineering, prompts, instructions and schemas are the second most frequent
way a design decision is implemented, after tests and formal
checks~\citep{diazvillegas2026mapping}. Curated skills lift pass
rates by 16.6 points across 18 model--harness configurations, and the gain
depends on the harness~\citep{li2026skillsbench}. Repository-level context
files for coding agents give no general improvement and add 20\% to
inference cost~\citep{gloaguen2026agentsmd}. Retrieved external knowledge
lowered the medal rate of one data-science agent on its easiest
tasks~\citep{yang2025rdagent}. Expert-provided knowledge raised the solve
rate of science agents by two points~\citep{chen2025scienceagentbench}. In
tabular AutoML, dataset descriptions in the prompt were the first such
intervention~\citep{hollmann2023caafe}. These studies switch the whole file
at once. We split the AutoDS-Tools instruction file into the part that names
the library and the part that prescribes a training discipline. An
automatic harness-evolution study reports that the system prompt
contributes little compared with tools and memory~\citep{harness2026prompt}.

\paragraph{Evaluation against tuned baselines} Tuned classical
baselines are rare in agentic AutoML papers.
GRACE-DS normalises against an untuned HistGradientBoosting model. The AutoML
benchmark reports average ranks with the Friedman and Nemenyi tests
recommended by Dem\v{s}ar, and scores scaled between a random-forest
baseline (0) and the best observed result
(1)~\citep{gijsbers2024amlb,demsar2006statistical}. TabReD publishes
eighteen methods, among them XGBoost, LightGBM and CatBoost, each
Optuna-tuned and averaged over fifteen seeds on temporal
splits~\citep{rubachev2024tabred}. We adopt that table as the reference and
the benchmark's conventions for ranks and normalised scores.

\paragraph{What remains open} The five lines of work leave one question
open for each hypothesis. Evidence on the harness comes mostly from coding
agents with frontier models, and systems papers change the language model
and the harness together. Whether the harness decides accuracy for a
mid-size open model on tabular data is open
(\ref{hyp:harness}). Systems differ in whether the agent writes
the model from the knowledge of its language model or hands it to a
library, and we found no study that measures this choice separately
(\ref{hyp:builder}). Studies of instruction files switch the whole file in
one harness, although its gain depends on the
harness~\citep{li2026skillsbench}. Whether explicit knowledge written for
one harness transfers to another is open (\ref{hyp:interaction}).
Answering the three questions needs a fixed language model, separated parts
and tuned reference methods. Section~\ref{sec:scheme} names the parts, and
Section~\ref{sec:design} describes the design that separates them.
