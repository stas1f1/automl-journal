\section{Introduction}
\label{sec:intro}

Automated machine learning (AutoML) frameworks search a predefined space
of pipelines~\citep{nikitin2022fedot,gijsbers2024amlb}. An agent built on a
large language model (LLM) works differently: it plans experiments, writes
and repairs code, reads execution logs and revises its own solution. Such an
agentic AutoML system has three parts that can be varied independently. The
first is the \emph{language model}. The \emph{harness} is the code
around the model: its tools, control flow, memory and prompts (the 2024--2025
literature calls it a scaffold~\citep{chan2025mlebench,hu2026beyondmodel}).
The \emph{instruction file} holds the standing instructions that
practitioners add to tell the agent which libraries to use and how to work.
Such files are now packaged as agent skills~\citep{li2026skillsbench}.

How much each of the three parts contributes to accuracy is not known. A
typical paper in the area introduces one system and reports an improvement
over a previous one. The language model, the harness, the instructions and
the evaluation protocol all change at once, and the published ablations
disagree as a result~\citep{toledo2025aira,brilliantov2026harness}. The
same holds for agentic software engineering at large: in a systematic
mapping of 94 peer-reviewed studies, only $19.8\%$ of evaluation records attribute the
evidence to an individual design decision, and $52.3\%$ evaluate complete
systems~\citep{diazvillegas2026mapping}. Agentic
AutoML systems are also rarely compared with the baseline a competent
practitioner would use: gradient boosting with tuned hyperparameters. In
the closest study the reference is an untuned gradient-boosting
model~\citep{tsymbalov2026graceds}.

This paper measures the three parts separately. We use one open-weight
model with 31 billion parameters (31B), gemma-4-31b-it, as the
language model of every system. We run three harnesses that represent distinct
designs of agentic AutoML (Figure~\ref{fig:systems}). \textbf{FEDOT.LLM} is a
workflow with four fixed stages in which the model configures the FEDOT
AutoML library. \textbf{AutoDS-Tools} is a system of six specialised agents
that communicate through written reports. \textbf{Terminus-2} is the
minimal single-agent harness of
Terminal-Bench~\citep{merrill2026terminalbench}, which gives the model a
shell and an execution loop. AutoDS-Tools comes with an expert instruction
file of about 5\,000 characters that names the library to use and prescribes
a training discipline. We switch this file on and off, split it into its two
parts and give it to Terminus-2. We also replace the language model with a
smaller and with a larger one. Every configuration runs in the Harbor
framework~\citep{harbor2026}, which records each attempt, error, token and
second. Accuracy is measured on the eight real-world tabular tasks of
TabReD~\citep{rubachev2024tabred}, which use temporal splits, against the
eighteen hyperparameter-tuned reference methods published with the
benchmark. Scores are normalised per task so that 0 is the weakest and 1 the
strongest published method. Two further settings change the starting point:
MLAgentBench~\citep{huang2024mlagentbench}, where each task begins with a
working script, and three tasks built from published scientific studies.

Three findings organise the paper.
\begin{enumerate}
\setlength{\itemsep}{1pt}
\item \textbf{The harness alone does not decide accuracy.} Without the
  instruction file the mean normalised scores of the three harnesses are
  close, and no pairwise difference between them is significant over the
  eight tasks. The harness decides reliability, wall-clock time and the set
  of tasks a system can attempt.
\item \textbf{Accuracy follows who builds and tunes the model.} Left to
  themselves, AutoDS-Tools and Terminus-2 write one gradient-boosting
  configuration by hand and never tune it. The part of the
  AutoDS-Tools instruction file that names the library hands the modelling to
  LightAutoML. The file raises the normalised score from $\nAutoDSOff$ to
  $\nAutoDS$ on all eight tasks, and that part alone is on par with tuned
  XGBoost. FEDOT.LLM follows the same rule task by task. It is the best of
  all methods on one classification task, where its backend starts from a
  boosting ensemble. On the four largest regression tasks it keeps an
  untuned random forest and ranks near last. The strongest published method, an MLP-PLR ensemble
  at $\nBest$, is out of reach of every configuration.
\item \textbf{The instruction file and the language model change
  reliability, and the direction depends on the harness.} Appended to
  Terminus-2, the same file leaves accuracy unchanged, and \ktBothLost{} to
  \ktToolLost{} of 24 trials end without a submission. Where a working script
  is supplied, the file leaves whole tasks without a submission. A larger
  language model removes such trials under Terminus-2 and adds them under
  AutoDS-Tools.
\end{enumerate}

The paper makes four contributions. The first is a controlled comparison of
three agentic AutoML harnesses on one open language model against tuned
reference methods, with paired statistics (Section~\ref{sec:results}). The
second is a set of ablations of the instruction file, the container image
and the language model, with the file split into its two parts and tested in
two harnesses and from two starting points (Section~\ref{sec:ablations}).
The third is a trace analysis of who builds the model and why the file fails
outside its harness (Section~\ref{sec:mechanism}). The fourth is the release
of all tasks, instruction files, traces and result tables.

These findings affect how agent leaderboards should be read.
Terminal-Bench~2.0 introduces Terminus-2 as a neutral harness so that a
leaderboard over it compares models~\citep{merrill2026terminalbench}, and
recent work on coding agents reports that elaborate harnesses add little
over a minimal one once the model is
strong~\citep{brilliantov2026harness,hu2026beyondmodel}. On tabular data
with a mid-size open model, our harness comparison agrees with that result.
Inside AutoDS-Tools the instruction file moves the score as much as
replacing the language model with a far larger one
(Section~\ref{sec:abl-language-model}), so a leaderboard built around one
harness measures its instructions as well as the model.

Sections~\ref{sec:related}--\ref{sec:design} cover related work, the systems
and the protocol. Sections~\ref{sec:results}--\ref{sec:mechanism} give the
results, the ablations and the trace analysis. Sections~\ref{sec:discussion}
and~\ref{sec:conclusion} discuss and conclude.
