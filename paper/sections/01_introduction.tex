\section{Introduction}
\label{sec:intro}

Attempts to automate the work of a data scientist go back fifty years.
Rice stated the algorithm selection problem in 1976: choose, for a given
dataset, the algorithm that performs best on it~\citep{rice1976algorithm}.
AutoML frameworks of the last decade solve a wider version of this problem.
They search a predefined space of pipelines and hyperparameters under a time
budget~\citep{thornton2013autoweka,feurer2015autosklearn,nikitin2022fedot,gijsbers2024amlb}.
Agents built on a large language model (LLM) are the latest step. They plan
experiments, write and repair code, read execution logs and revise their own
solution~\citep{trirat2025automlagent,guo2024dsagent,chan2025mlebench}. Their
search space is open, and their behaviour depends on three parts specific to
agents. The \emph{language model} makes the decisions. The \emph{harness} is
the code around the model: its tools, control flow, memory and prompts, also
called a scaffold~\citep{chan2025mlebench,hu2026beyondmodel}. The
\emph{instruction file} holds the standing instructions that practitioners
add to tell the agent which libraries to use and how to work. Such files are
now packaged as agent skills~\citep{li2026skillsbench}.

How much each of the three parts contributes to accuracy is not known. A
typical paper in the area introduces one system and reports an improvement
over a previous one. The language model, the harness, the instructions and
the evaluation protocol all change at once, and the published ablations
disagree as a result~\citep{toledo2025aira,brilliantov2026harness}. The
same holds for agentic software engineering at large: in a systematic
mapping of 94 peer-reviewed studies, only $19.8\%$ of evaluation records attribute the
evidence to an individual design decision, and $52.3\%$ evaluate complete
systems~\citep{diazvillegas2026mapping}. Agentic
AutoML systems are also rarely compared with the baseline a competent
practitioner would use: gradient boosting with tuned hyperparameters. In
the closest study the reference is an untuned gradient-boosting
model~\citep{tsymbalov2026graceds}.

Three hypotheses about the sources of accuracy and reliability, H1 to H3,
frame the problem. They apply to any agentic AutoML system, and
Section~\ref{sec:scheme} states them in terms of a general scheme of such
systems (Figure~\ref{fig:scheme}).
\begin{enumerate}
\renewcommand{\labelenumi}{\textbf{H\arabic{enumi}.}}
\renewcommand{\theenumi}{H\arabic{enumi}}
\setlength{\itemsep}{1pt}
\item \textbf{The harness alone does not decide accuracy.}\label{hyp:harness}
  A harness decides who plans, in what order the steps run and how errors
  are repaired. The modelling decisions come from the same language model in
  every harness. If every harness ends with the same kind of model, accuracy
  should be close. The harness should then show in reliability, run time and
  the range of tasks a system can take.
\item \textbf{Accuracy follows who builds and tunes the model.}\label{hyp:builder}
  An agent that writes its own code is likely to reproduce a common default
  configuration. Tuning it takes a search that the agent must decide to run
  and pay for in time. An AutoML library runs such a search by design. The
  procedure that builds the model should therefore matter more than the
  harness that calls it.
\item \textbf{The instruction file and the language model change
  reliability, and the direction depends on the harness.}\label{hyp:interaction}
  An instruction file is written for one harness and assumes its control
  flow, for example a repair loop that waits for a long fit to finish. A
  different language model changes how much the agent reasons within the
  same time limit. One and the same file or model can then help in one
  harness and harm in another.
\end{enumerate}

The paper makes four contributions. The first is a general scheme of
agentic AutoML that separates the language model, the harness, the
instruction file and the procedure that builds the model
(Section~\ref{sec:scheme}). The second is an experimental design that
separates these parts. The language model and the tasks are fixed, the
instruction file is split into its two parts, and accuracy is read against
tuned reference methods apart from the trials without a submission
(Section~\ref{sec:design}). The third is a test of the three hypotheses on
three harnesses that cover the main patterns of the scheme
(Sections~\ref{sec:results}--\ref{sec:mechanism}). The fourth is a set of
design rules that follow from the hypotheses
(Section~\ref{sec:rules}). All tasks, instruction files, traces and
result tables are released.

We test the hypotheses with one open-weight model with 31 billion
parameters, gemma-4-31b-it, as the language model of every system.
FEDOT.LLM is a workflow with four fixed stages around the FEDOT AutoML
library. AutoDS-Tools is a system of six agents that communicate through
written reports. Terminus-2 is the minimal single-agent harness of
Terminal-Bench~\citep{merrill2026terminalbench}, a shell with an execution
loop (Figure~\ref{fig:systems}). The instruction file of AutoDS-Tools, about
5\,000 characters, names the library to use and prescribes a training
discipline. We switch it on and off, split it into these two parts and
append it to Terminus-2. We also replace the language model with a smaller
and a larger one. Accuracy is measured on the eight tabular tasks of TabReD
with temporal splits, against the eighteen tuned reference methods published
with it~\citep{rubachev2024tabred}. MLAgentBench~\citep{huang2024mlagentbench}
and three tasks from published scientific studies change the starting point.
All runs go through the Harbor framework~\citep{harbor2026}, which records
each trial, error, token and second.

Section~\ref{sec:related} reviews related work.
Section~\ref{sec:scheme} describes the general scheme of agentic AutoML and
states the hypotheses in its terms. Section~\ref{sec:systems} describes the
three harnesses and the instruction file, and Section~\ref{sec:design} the
experimental design. Sections~\ref{sec:results} to~\ref{sec:mechanism}
give the results, the ablations and the trace analysis.
Section~\ref{sec:discussion} discusses them, and
Section~\ref{sec:conclusion} concludes.
