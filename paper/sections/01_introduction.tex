\section{Introduction}
\label{sec:intro}

% minimum here; each one is reported once in Sections 5 and 6.

Automated machine learning (AutoML) frameworks search a predefined space
of pipelines~\citep{nikitin2022fedot,gijsbers2024amlb}. An agent built on a
large language model (LLM) works differently: it plans experiments, writes
and repairs code, reads execution logs and revises its own solution. Such an
agentic AutoML system has three parts that can be varied independently. The
\emph{backbone} is the language model. The \emph{harness} is the code
around the model: its tools, control flow, memory and prompts (the 2024--2025
literature calls it a scaffold~\citep{chan2025mlebench,hu2026beyondmodel}).
The \emph{instruction file} holds the standing instructions that
practitioners add to tell the agent which libraries to use and how to work;
such files are now packaged as agent skills~\citep{li2026skillsbench}.

How much each of the three parts contributes to accuracy is not known. A
typical paper in the area introduces one system and reports an improvement
over a previous one, with the backbone, the harness, the instructions and
the evaluation protocol all changing at once, and the published ablations
disagree as a result~\citep{toledo2025aira,brilliantov2026harness}. Agentic
AutoML systems are also rarely compared with the baseline a competent
practitioner would use, gradient boosting with tuned hyperparameters; when
gradient boosting appears, it usually runs with its defaults.

This paper measures the three parts separately. We use one open-weight
model with 31 billion parameters (31B), \texttt{gemma-4-31b-it}, as the
backbone of every system, and run three harnesses that represent distinct
designs of agentic AutoML (Figure~\ref{fig:systems}): \textbf{FEDOT.LLM}, a
workflow with four fixed stages in which the model configures the FEDOT
AutoML library; \textbf{AutoDS-Tools}, a system of six specialised agents
that communicate through written reports; and \textbf{Terminus-2}, the
minimal single-agent harness of
Terminal-Bench~\citep{merrill2026terminalbench}, which gives the model a
shell and an execution loop. AutoDS-Tools ships with an expert instruction
file of about 5\,000 characters that names the library to use and prescribes
a training discipline. We switch this file on and off, split it into its two
parts and give it to Terminus-2. We also replace the backbone with a smaller
and with a larger model. Every configuration runs in the Harbor
framework~\citep{harbor2026}, which records each attempt, error, token and
second. Accuracy is measured on the eight real-world tabular tasks of
TabReD~\citep{rubachev2024tabred}, which use temporal splits, against the
eighteen hyperparameter-tuned reference methods published with the
benchmark. Scores are normalised per task so that 0 is the weakest and 1 the
strongest published method. Two further settings change the starting point:
MLAgentBench~\citep{huang2024mlagentbench}, where each task begins with a
working script, and three tasks built from published scientific studies.

Three findings organise the paper.
\begin{enumerate}
\setlength{\itemsep}{1pt}
\item \textbf{Without the instruction file, the harnesses differ little in
  mean accuracy and a great deal task by task.} The mean normalised scores of
  the three harnesses are close, and no pairwise difference between them is
  significant over the eight tasks; FEDOT.LLM is the best of all methods on
  one task and near last on four. The harness does decide reliability,
  wall-clock time and the set of tasks a system can attempt.
\item \textbf{The instruction file raises accuracy inside its own harness
  and fails outside it.} Inside AutoDS-Tools the file raises the normalised
  score from $\nAutoDSOff$ to $\nAutoDS$ and improves all eight tasks.
  Appended to Terminus-2, the same file leaves accuracy unchanged and ends
  about half of the trials without a submission; where a working script is
  supplied, it leaves whole tasks without a submission.
\item \textbf{Accuracy follows whether an AutoML library builds the model.}
  The part of the file that carries the gain names LightAutoML, and with it
  AutoDS-Tools hands the modelling to that library in every trial. Without
  it, AutoDS-Tools and Terminus-2 write one gradient-boosting configuration
  by hand and never tune it. AutoDS-Tools with the library instruction alone
  is on par with tuned XGBoost; the strongest published method, an MLP-PLR
  ensemble at $\nBest$, is out of reach of every configuration.
\end{enumerate}

The contributions are: (i) a controlled comparison of three agentic AutoML
harnesses on one open backbone against tuned reference methods, with paired
statistics (Section~\ref{sec:results}); (ii) ablations of the instruction
file, the container image and the backbone, with the file split into its two
parts and tested in two harnesses and from two starting points
(Section~\ref{sec:ablations}); (iii) a trace analysis of who builds the
model and why the file fails outside its harness
(Section~\ref{sec:mechanism}); and (iv) the release of all tasks,
instruction files, traces and scripts.

These findings affect how agent leaderboards should be read.
Terminal-Bench~2.0 introduces Terminus-2 as a neutral scaffold so that a
leaderboard over it compares models~\citep{merrill2026terminalbench}, and
recent work on coding agents reports that elaborate harnesses add little
over a minimal one once the model is
strong~\citep{brilliantov2026harness,hu2026beyondmodel}. On tabular data
with a mid-size open model, our harness comparison agrees with that result.
Inside AutoDS-Tools the instruction file moves the result further
than a backbone swap that changes the API cost \axPriceSpread$\times$
(Section~\ref{sec:abl-backbone}), so a leaderboard built around one harness
measures its instructions as well as the model.

Sections~\ref{sec:related}--\ref{sec:design} cover related work, the systems
and the protocol; Sections~\ref{sec:results}--\ref{sec:mechanism} give the
results, ablations and trace analysis; Sections~\ref{sec:discussion}
and~\ref{sec:conclusion} discuss and conclude.
